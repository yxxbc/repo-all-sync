# repo-all-sync

Sync a Git repository to **GitHub**, **Gitee** and **CNB** from one command:
create the mirror repositories, push the source, and publish release assets.

No dependencies. Node.js >= 20.

## Install

```bash
npm install -g repo-all-sync
# or run without installing
npx --yes repo-all-sync help
```

Requirements:

- `git`
- `gh` for GitHub repository creation / GitHub releases (optional)
- `cnb` for creating CNB repositories (optional; source pushes and release uploads use the HTTP API)

## Configure

Tokens are read from the environment (recommended) or
`~/.config/repo-all-sync/config.json`:

```bash
export GITEE_HOST=gitee.com
export GITEE_OWNER=your-gitee-name
export GITEE_TOKEN=...

export CNB_HOST=cnb.cool
export CNB_GROUP=your-cnb-group
export CNB_TOKEN=...
```

Or keep them in a private env file:

```bash
cp skill/tokens.env.example ~/.config/repo-all-sync.env
chmod 600 ~/.config/repo-all-sync.env
set -a; source ~/.config/repo-all-sync.env; set +a
```

`repo-all-sync doctor` checks tools, config and token presence **without printing token values**.

## Usage

```bash
# create/verify mirror repos (safe to re-run; --dry-run prints only)
repo-all-sync create --dry-run
repo-all-sync create

# push the current branch to all three
repo-all-sync push --dry-run
repo-all-sync push

# publish release assets to Gitee and CNB
repo-all-sync release --version 1.2.3 --assets dist --notes notes.md

# also create/upload the GitHub release via gh
repo-all-sync release --version 1.2.3 --assets dist --notes notes.md --github
```

Common options:

| Option | Meaning |
| --- | --- |
| `--repo <name>` | mirror repository name (default: directory name) |
| `--branch <name>` | source branch (default: `main`) |
| `--gitee-owner <name>` | Gitee owner; defaults to `GITEE_OWNER`, then the token user |
| `--cnb-group <name>` | CNB group; defaults to `CNB_GROUP` |
| `--github-remote <name>` | GitHub remote (default: `origin`) |
| `--github-owner <name>` | create the GitHub repo under this user/org (default: the `gh` account) |
| `--dry-run` | print actions without changing anything |
| `--json` | reserved for machine-readable output |

Environment overrides: `REPO_NAME`, `BRANCH`, `GITHUB_OWNER`, `GITEE_HOST`, `GITEE_OWNER`,
`GITEE_TOKEN`, `CNB_HOST`, `CNB_GROUP`, `CNB_TOKEN`, `CNB_API`, `RAS_CONFIG`.

## How the mirrors work

- **GitHub** — `git push <remote> HEAD:<branch>`; the remote must exist or be created with `gh`.
- **Gitee** — full-history fast-forward push over HTTPS with the token.
- **CNB** — pushes a **snapshot** of the current tree (single commit, force push). A full history
  push can fail when the repository contains Git LFS objects that are not available locally;
  the snapshot keeps the mirror usable without requiring the LFS store. The snapshot commit
  keeps the author of the current `HEAD` commit.

## Releases

`release` creates the release if needed, uploads assets, and skips assets that already exist
with the same size (re-uploads when the size changed).

- Gitee: creates a release and uploads attachments through `/releases/{id}/attach_files`.
- CNB: creates a draft release, requests upload URLs, uploads, confirms, then publishes it.
- GitHub: only when `--github` is given; delegates to `gh release create` / `gh release upload`.

Application-specific update manifests (for example wmlUpdate's `manifest.json`) are **not**
generated by this CLI. Keep that in the repository's release script and upload the manifest as
one of the release assets, or generate it before calling `repo-all-sync release`.

## Local development

```bash
npm test
node bin/repo-all-sync.mjs help
npm link        # optional: makes `repo-all-sync` available globally
```

## Security

- Tokens are only read from the environment or the config file; they are never printed.
- Do not commit `tokens.env`, `.env` or `~/.config/repo-all-sync/config.json`.
- Use tokens with the smallest scopes needed: repository write + release write.
